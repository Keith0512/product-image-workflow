# 主圖／詳情頁差異預覽（固定交付）

## 內容與範圍

每個商品、每套製作模式的成果根目錄固定交付 `主圖詳情頁差異預覽.html`，取代舊的單欄 `商品詳情預覽.html`。處理報告及整批總報告連到各商品的比較頁，最終回覆也提供入口。

- 左側是實際原始檔，右側是本次最終重製版本；兩欄各有獨立的上下捲動區、跳圖及適寬／100%控制。縮放或捲動其中一側，不移動另一側。
- 以「主圖」「詳情頁」切換，各側保留自己的完整閱讀順序與張數。重設計可能整併、拆頁或重排，不強制同編號配對，也不宣稱自動判定設計正確。
- 完整製作包含所有原始主圖、原始詳情，以及最終 `1_主圖`、完整 `3_詳情頁`。不拿S切片取代完整3版，也不漏掉高資訊量封面。
- 只做封面時僅列主圖；只做批次時列本次適用分類；僅M重跑時，在詳情頁列已確認的唯一來源與最終M版。選項、浮水印或MOMO版本只有本次已製作且需要比較時才另列分類，不為預覽新增製圖工作。
- 原始圖即使有淘汰的活動或錯誤資訊也原樣保留，讓美編看出差異；已核定的修正依據留在報告，不把原圖先修成重製稿。

## 可攜與來源保護

頁面使用內嵌CSS／JavaScript及相對圖片路徑，離線可開啟，不使用CDN或外部服務。完整保留圖片位元組，不重新壓縮、縮放、裁切或套濾鏡；原尺寸檔案另可點開檢視。

比較素材副本位於 `0_處理紀錄/差異預覽素材/`，`0_處理紀錄/差異預覽索引.json` 記錄來源完整路徑、分類、排序、尺寸及SHA-256。HTML只用相對副本路徑，搬移時保留整份成果資料夾。商品原圖及成果不可隨技能推送至GitHub。

不覆寫已有比較頁、索引或素材資料夾。重新生成時建立新版本，可從已驗收的既有商品成果生成「僅比較頁重跑」版本，明確記錄原稿與成品的來源版本；不必重新生成商品圖片。

## 產生方式

先用盤點結果及人工確認的圖片角色準備計畫，不依檔名猜測角色。每側清單依確認後的閱讀順序排列，通常採自然排序；排除AppleDouble、草稿、預覽、報告及歷史輸出。來源可以是絕對路徑，或相對於計畫檔的路徑：

```json
{
  "title": "本次商品與販售版本",
  "groups": [
    {
      "id": "main",
      "label": "主圖",
      "original": ["原始主圖01.jpg", "原始主圖02.jpg"],
      "remade": ["最終主圖01.jpg"]
    },
    {
      "id": "detail",
      "label": "詳情頁",
      "original": ["原始詳情01.jpg", "原始詳情02.jpg"],
      "remade": ["完整3版詳情01.jpg"]
    }
  ]
}
```

分類id唯一；每個分類兩側都須非空，但張數可不同。不適用分類不建立。將計畫保存在本次版本的 `0_處理紀錄/差異預覽計畫.json`，從入口技能目錄執行：

```bash
python scripts/build_compare_preview.py --plan /path/to/差異預覽計畫.json --output /path/to/本次成果
```

使用專用環境及同層批次技能的Pillow依賴。腳本先解碼所有來源，任一缺失或損壞就停止，不靜默跳圖；全部預檢通過後才寫入頁面與原樣素材副本。產生成功只證明檔案已建立，索引的 `NOT_VERIFIED_BY_TOOL` 不能當作視覺PASS。

## 必要驗收

1. 對照盤點及最終交付清單，逐分類確認左右順序、張數及SHA-256，確保右側不是草稿，原圖未被修改。兩側張數不同本身不是錯誤。
2. 實際在瀏覽器開啟，檢查所有圖片可載入及原尺寸連結可用，沒有外部資源依賴或斷圖；核對畫面呈現與原尺寸標示。
3. 分別捲動左右欄、跳至中段及末張、切換分類、各側切換適寬／100%；確認另一欄不跟著移動，分類切回可回到各欄先前位置。
4. 檢查桌面與窄螢幕仍保有左右兩欄、各自可捲動且控制可操作；100%可在欄內水平捲動，不撐開整個頁面。
5. 在處理報告記錄瀏覽器檢查與素材驗證。缺頁、缺圖或來源不符須修正，必要檢查未完成就保留未完成狀態；既有圖片保真、文案及內容覆蓋驗收照常執行。
