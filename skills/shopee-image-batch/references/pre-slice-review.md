# 分割前視覺驗收

這是來源整理稿與S／M製作之間的必要關卡。完整批次逐張驗收主圖、適用選項及本次完整3版；僅M重跑逐張驗收唯一來源。MOMO編輯版完成選圖與重排後，所有M編輯稿再獨立驗收一次，通過才編碼輸出。不因舊版曾通過、OCR成功或檔案規格正確而省略，也不要求使用者例行逐張批准。

繁中重設計同樣適用四項檢查，另依[共用重設計規則](../../product-image-workflow/references/redesign.md)逐圖檢查商品與購買理由、情境使用感受、賣點畫面證據、美感與閱讀節奏、商品與內容一致性。具體觀察及修正記入商品製作摘要與報告；四項技術檢查PASS不能代替商業設計通過。文字布局對照本次設計摘要，商品對照真實來源；有意且合理的新資訊框／背景投影不當作殘影，但不得掩蓋舊字或改造商品。重新設計的每張圖須重新驗收，不能沿用原風格PASS。參考圖編輯另逐項對照結構與SKU，原商品區域合成核對邊緣、接地及光影；不把兩者都宣稱原像素保留。

## 實際檢查

完成去字、補景、繁中排版與尺寸規格化後，實際打開將要使用的圖片。先看整張版面及跨圖的一致性，再以 100% 像素檢查每個文字／修復區域、小字與接縫，最後以手機閱讀寬度確認可讀性。長圖分區檢視要覆蓋全圖並保留上下文；不能只看縮圖、抽查幾張或檢查未修改的原圖。

逐張檢查四項：

| 紀錄欄位 | 通過條件 |
|---|---|
| `typography` | 繁中字形、數值與單位正確；同層級文字的字型、字級、字重、字距、行距及對齊一致；沒有突兀大小、擠字、溢出、切邊、重疊或難讀小字。保留有意的主副標層級，不把所有文字改成一樣大。 |
| `text_cleanup` | 舊字及其描邊、投影清乾淨，沒有簡體宣傳殘字、雙重筆畫、鬼影、殘影或新舊字疊在一起。對照原圖區分應保留的實體印刷。 |
| `background` | 修復處無多餘黑灰陰影、光暈、模糊色塊、矩形邊界、重複紋理、接縫或抹除痕跡。對照原圖保留商品真實投影、反光與原有合理設計效果，不為了去陰影而抹掉商品細節。 |
| `product_integrity` | 商品、配件、Logo、顏色、比例、結構及實體標示與來源一致，清字與補景未傷及商品。完整3版／S／固定切片無意外漏失或重複；MOMO編輯版的取捨符合已核對清單，必要資訊無漏失，不把正常精簡判成商品缺損。 |

## 修正與放行

發現問題 → 記錄圖檔與座標／區域 → 回到無損整理稿局部修正 → 重新匯出 → 複檢修改區及整張版面。相同問題連續兩次修正仍無法解決時，保留完整稿與問題對照，標 REVIEW 並說明限制，不無限重試。

**全部適用來源、全部檢查項目都有實際PASS證據，才進入S整合／M編輯或完整固定切片；M編輯稿全部通過才編碼輸出。** 未檢視、證據缺漏或視覺REVIEW／FAIL時停在對應整理稿，不以輸出待審稿繞過關卡。多商品預設停在當前商品，完成該商品全部必要產出及最終驗收後才繼續下一個；只有使用者明確指定改序、跳過或跨商品並行時才調整。未完成必要階段依交付狀態記錄並說明原因。必要資訊衝突另做內容REVIEW，不得用省略或虛填PASS取得M正式候選。

驗收後只要重新去字、補景、換字型／字級、改排版、縮放、壓縮或變更實際來源檔，就使該圖舊紀錄失效，重新檢視並記錄新雜湊。不要只更新來源清單的雜湊卻沿用舊驗收。M 為避開切字而調版後也相同。已產生的衍生切片須用新通過的來源重新產生；不覆寫歷史交付。

切片後仍要檢查切線、完整覆蓋與壓縮品質；分割前 PASS 不代表最終切片自動 PASS。

## 逐張紀錄

在 `0_處理紀錄/` 保存版本化的 `分割前視覺驗收-v01.json` 及整圖／局部對照預覽。每列記實際被檢視的圖片絕對路徑、SHA-256、四項結果、實際觀察與預覽位置；有修正時保留前後對照及複檢結果。下例是格式，不能直接當成驗收證據：

```json
{
  "sources": [
    {
      "path": "實際整理稿的絕對路徑",
      "sha256": "目前圖片的實際SHA256",
      "visual_review": {
        "sha256": "實際檢視當下該圖的SHA256",
        "status": "PASS",
        "typography": "PASS",
        "text_cleanup": "PASS",
        "background": "PASS",
        "product_integrity": "PASS",
        "evidence": "逐張整圖及100%局部檢視的實際發現、對照預覽位置與修正複檢結果"
      }
    }
  ]
}
```

沒有宣傳文字時，仍實際確認字區不適用、背景與商品無誤，在 evidence 說明後才記 PASS，不由程式自動填入。`visual_review.sha256` 綁定已驗收版本；不能沿用原始素材或前一修訂的雜湊。

先用 `shopee_tools.py check-visual` 核對紀錄與全部適用資料夾（每個各一個`--source`）；S開始前含完整3版，完整批次也含主圖與適用選項。M計畫每個`sources`帶入來源驗收；MOMO編輯模式每個`pages`另有該編輯稿驗收。編輯稿可另建含`sources`清單的驗收JSON，對本次M編輯稿資料夾執行`check-visual`。`build_m.py`在建立輸出前阻擋來源或編輯稿的缺項、未通過或雜湊不符。

工具只能驗證紀錄及版本，不能自動看出鬼影或字級不一致，不能反過來把工具成功當成已目視驗收。
