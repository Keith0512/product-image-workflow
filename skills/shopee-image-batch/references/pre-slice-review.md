# 分割前視覺驗收

這是整理稿與 S／M 切片之間的必要關卡。完整批次逐張驗收本商品的主圖、適用選項圖及本次 `3_詳情頁`；僅 M 重跑逐張驗收選定的唯一來源。不因舊版曾通過、OCR 成功或檔案規格正確而省略，也不要求使用者例行性地逐張批准。

## 實際檢查

完成去字、補景、繁中排版與尺寸規格化後，實際打開將要使用的圖片。先看整張版面及跨圖的一致性，再以 100% 像素檢查每個文字／修復區域、小字與接縫，最後以手機閱讀寬度確認可讀性。長圖分區檢視要覆蓋全圖並保留上下文；不能只看縮圖、抽查幾張或檢查未修改的原圖。

逐張檢查四項：

| 紀錄欄位 | 通過條件 |
|---|---|
| `typography` | 繁中字形、數值與單位正確；同層級文字的字型、字級、字重、字距、行距及對齊一致；沒有突兀大小、擠字、溢出、切邊、重疊或難讀小字。保留有意的主副標層級，不把所有文字改成一樣大。 |
| `text_cleanup` | 舊字及其描邊、投影清乾淨，沒有簡體宣傳殘字、雙重筆畫、鬼影、殘影或新舊字疊在一起。對照原圖區分應保留的實體印刷。 |
| `background` | 修復處無多餘黑灰陰影、光暈、模糊色塊、矩形邊界、重複紋理、接縫或抹除痕跡。對照原圖保留商品真實投影、反光與原有合理設計效果，不為了去陰影而抹掉商品細節。 |
| `product_integrity` | 商品、配件、Logo、顏色、比例、結構及實體標示與來源一致，清字與補景未傷及商品，內容無漏失或重複。 |

## 修正與放行

發現問題 → 記錄圖檔與座標／區域 → 回到無損整理稿局部修正 → 重新匯出 → 複檢修改區及整張版面。相同問題連續兩次修正仍無法解決時，保留完整稿與問題對照，標 REVIEW 並說明限制，不無限重試。

**只有全部適用圖片、全部檢查項目都有實際 PASS 證據，才可開始本商品的 S／M 合併、切割及壓縮。** 未檢視、證據缺漏、任何 REVIEW／FAIL 或疑點尚未解決時，停在整理稿；不得先切片後補驗收，也不得把有瑕疵的切片標成 REVIEW 就當作繞過關卡。其他已完整通過的商品可繼續。尚未完成的必要切片在整體交付狀態依既有規則記 FAIL，並寫明是因前置驗收未通過而暫停。

驗收後只要重新去字、補景、換字型／字級、改排版、縮放、壓縮或變更實際來源檔，就使該圖舊紀錄失效，重新檢視並記錄新雜湊。不要只更新來源清單的雜湊卻沿用舊驗收。M 為避開切字而調版後也相同。已產生的衍生切片須用新通過的來源重新產生；不覆寫歷史交付。

切片後仍要檢查切線、完整覆蓋與壓縮品質；分割前 PASS 不代表最終切片自動 PASS。

## 逐張紀錄

在 `0_處理紀錄/` 保存版本化的 `分割前視覺驗收-v01.json` 及整圖／局部對照預覽。每列記實際被檢視的圖片絕對路徑、SHA-256、四項結果、實際觀察與預覽位置；有修正時保留前後對照及複檢結果。下例是格式，不能直接當成驗收證據：

```json
{
  "sources": [
    {
      "path": "實際整理稿的絕對路徑",
      "sha256": "目前圖片的實際SHA256",
      "visual_review": {
        "sha256": "實際檢視當下該圖的SHA256",
        "status": "PASS",
        "typography": "PASS",
        "text_cleanup": "PASS",
        "background": "PASS",
        "product_integrity": "PASS",
        "evidence": "逐張整圖及100%局部檢視的實際發現、對照預覽位置與修正複檢結果"
      }
    }
  ]
}
```

沒有宣傳文字時，仍實際確認字區不適用、背景與商品無誤，在 evidence 說明後才記 PASS，不由程式自動填入。`visual_review.sha256` 綁定已驗收版本；不能沿用原始素材或前一修訂的雜湊。

先用 `shopee_tools.py check-visual` 核對紀錄與全部適用資料夾（每個資料夾各一個 `--source`）；S 開始前必須包含完整的本次 3 版清單，完整批次也包含主圖與適用選項圖。M 計畫的每個 sources 項目帶入該張實際驗收的 `visual_review`，`build_m.py` 會在建立輸出前阻擋未通過、缺項或版本不符的來源。

工具只能驗證紀錄及版本，不能自動看出鬼影或字級不一致，不能反過來把工具成功當成已目視驗收。
