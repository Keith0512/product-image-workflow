# MOMO必要詳情編輯

僅在使用者明確要求M詳情／僅M重跑時啟用；預設不生成M詳情，啟用本模式也不連帶生成MOMO封面。本模式把完整繁中資料編輯成最多20頁、每頁1000×1500、每張≤500,000 bytes的必要詳情。這是本次技能交付規格；實際平台規則另依使用者資訊或已查證資料。原來源與3版只讀保留，M版可以選圖、整併、摘要、重排；不自動上架。

## 內容取捨

逐張閱讀唯一來源，先抽出資訊項目，盤點全部來源後才規劃頁數。以買家能辨識正確商品、比較適用性、確認收到什麼並正確使用為判斷依據。

| 類別代碼 | 必要資訊與適用性 |
|---|---|
| identity | 商品、型號、實際販售版本／顏色及會影響購買的SKU差異；必填 |
| specifications | 尺寸、重量、材質、容量、性能及適用條件等主要規格；必填 |
| package_contents | 標準包裝內容、數量、套組差異、另購與場景道具界線；必填 |
| limitations | 相容性、適用範圍、使用環境及其他重要限制；依實際來源記適用或不適用與依據 |
| operation | 必要搭設／安裝／操作／收納與保養步驟；依商品記適用性，不能任意略去關鍵步驟 |
| safety | 警語、壓力／承重等安全數值、禁忌及條件；有來源安全資訊即須保留 |
| key_features | 影響購買的核心功能與代表性示意；依商品記適用性 |
| supporting | 非必要的情境、裝飾、促銷、重複賣點等，可有理由地省略；不代替前述必要盤點 |

「不適用」是資訊類別的實際盤點結論，不是輸出資料夾N/A，也不能用來掩蓋缺資料。重要來源矛盾保留證據並待審，不擅選一個數字、取平均、放寬限制或省略矛盾數值。必要資訊無法確認時不產生可發布的正式候選。

相同賣點留下最完整清楚的表述；多張近似照片選代表圖；分散的規格、功能與配件說明可整併為表格。非販售版本示意只有解釋差異所需才保留並清楚標示。文案可縮短，但數值、單位、條件、警語及另購界線不能遺漏或改變。不要把原廠檢測文件重畫成新證書。

不需使用者例行逐張選圖。只有商品歸屬、關鍵事實或必要資訊不足等實際缺口才需釐清。被省略的正常資料留在3版或原來源，以取捨清單引用，不複製整套到第6資料夾。

## 頁數與排版

可先以16–18頁估算，為必要資訊留調整空間；依商品複雜度增減，不套固定章節頁數，也不湊滿20。先安排規格／包裝／操作／安全等必要內容，再放核心賣點與代表照片。

每頁先完成1000×1500無損RGB PNG。標題、字行、表格列、警語及同一步驟的圖說完整落在頁內。允許合理留白；不把全張長圖縮成小卡拼頁或拉伸商品。照片裁切須保留所說明的商品結構；使用原圖等比例裁切縮放，不以生圖重畫商品。

來源先依分割前規則逐張驗收；重排後每一張M編輯稿再以整頁、100%文字區及手機寬度檢視，重新綁定實際SHA-256。3版通過不能代替M編輯稿通過。重排或改圖後重新驗收，輸出JPEG後再查可讀性與內容覆蓋。

若仍超20頁，先合併重複、縮短非必要敘述、調整圖片面積與版面；不能截前20頁、砍警語或壓小字取得通過。必要內容確實無法容納時保留完整3版與M作業稿並REVIEW，說明阻擋項目。

## 工具計畫

`build_m.py` 預設 `momo-editorial`，輸出前先驗證紀錄、頁數、尺寸、雜湊及必要項目對應。工具不負責選圖或排文字；代理先依此文件製作編輯稿。所有路徑均為絕對路徑，所有視覺與內容PASS須有實際觀察，不能複製示例聲明。

頂層欄位：

- `mode`: `momo-editorial`；省略也預設此模式。完整切片須明確填`fixed-1500`。
- `result_root`、可選`explicit_source`：依唯一來源規則選定。`sources`須包含完整自然排序清單、實際SHA-256與各圖`visual_review`；第2張起另有已確認的`boundary_before.type/evidence`，見[工具契約](tools.md)。不能先刪來源列來隱藏取捨，不使用`trim_top_normalized_px`裁剪內容。
- `source_reviewed: true`、`review_evidence`：實際商品／SKU／接縫核對。
- `content_review`: `status: PASS`及`evidence`，記必要事實、條件、安全與矛盾的核對結論。
- `coverage_categories`：前7個類別各一列`id`、`applicability`（`required`或`not_applicable`）及`reason`。前3類永遠必填。
- `content_items`：全部資訊項目的保留、整併、排除清單；每張來源至少被一項引用，可一項對應多張來源，也可同一來源拆成多項。內容盤點是否確實涵蓋全部重要事實仍須實際檢視，工具不會自動理解圖片。
- `pages`：1–20頁，`page`由1連號，`path`、`sha256`與綁定同雜湊的四項`visual_review`。只能使用實際已排好的1000×1500 RGB PNG；不可重複同一頁內容。

單一內容項目的欄位示意如下；這是片段，實際計畫仍須補齊全部來源、適用類別與實際頁面：

```json
{
  "id": "inner-size",
  "category": "specifications",
  "required": true,
  "decision": "merge",
  "reason": "將已核對的尺寸資訊併入規格表，保留全部數值與單位",
  "original_text": "來源實際文案或影像摘要：250×280×200cm",
  "final_text": "內帳尺寸：約250×280×200cm",
  "protected_values": ["250", "280", "200cm"],
  "source_regions": [
    {
      "path": "/本次唯一來源/詳情_01.jpg",
      "sha256": "實際來源SHA256",
      "box": [0, 0, 1000, 800]
    }
  ],
  "placements": [
    {"page": 2, "box": [50, 180, 950, 360], "operation": "text_reflow"}
  ]
}
```

`decision`為`keep`／`merge`／`omit`，每項記`reason`。必要項目不允許omit；省略項目`final_text`為空、`placements`為空，但仍有來源區域與原因。保留／整併項目均須對應頁碼與區域。受保護數值／單位／條件列在`protected_values`，文字正規化後仍須出現在來源摘要及最終文案；這只檢查已列項目，不取代人工核對漏列值。

所有區域採左上原點、半開`[x0,y0,x1,y1)`整數座標。`source_regions.box`是EXIF轉正後原圖像素；`placements.box`是1000×1500頁面像素。`text_reflow`表示來源文案衍生排字，不能宣稱原始像素保留。`image_crop`另填`source_region`（0起算索引），對應該原圖區域等比例裁切縮放，不改變商品比例；來源照片與頁面中的實際一致性仍須目視核對。

## 交付與驗收

工具輸出`M計畫.json`、`M切片紀錄.json`、`M必要資訊覆蓋.csv`、`M內容取捨.csv`及來源區域對應CSV；無損稿存`0_處理紀錄/work/M編輯稿/`。記錄有效不等於語意正確或壓縮後視覺通過。

5版只收1–20頁、每頁1000×1500、各≤500,000 bytes的候選。整套有任何超容量頁時，全部JPEG只放`6_待人工審核/M容量異常/`；不在5版另留相同副本。重排後用新版本輸出，保護歷史成果。

報告分列：必要資訊的來源與成品頁碼、精簡項目與原因、編輯前後頁數、逐頁尺寸／容量／雜湊、來源與編輯稿的獨立視覺紀錄、壓縮後實際核對與未解問題。來源矛盾／缺漏與影像品質分開記錄，不能用頁數合格掩蓋內容問題。
